# ito (IoT操作)

家のエアコン・灯り・温湿度計を扱うスクリプト。このディレクトリで直接動かす（`/workspace/bot/workspace/ito`）。初回は `uv venv venv && uv pip install -p venv -r requirements.txt`。

- `main.py`: FastAPI サーバ（127.0.0.1:9094）。SwitchBot API でエアコン・灯り・センサーを操作する。`static/index.html` はダッシュボード。
- `switchbot.py` / `switchbot_launcher.py`: SwitchBot API クライアントと、認証情報を環境変数に読み込んで起動するランチャ。トークン類はレポジトリに置かない。
- `acctl.py <夏ゆるめ|夏標準|夏厳しめ|冬ゆるめ|冬標準|冬厳しめ>`: 5分おきに温湿度を読み、ルールに従ってエアコンに信号を送る。`ゆるめ` / `標準` / `厳しめ` は夏の別名。ログは `aclog/log.csv`。
- `acgraph.py [hours]`: ログから温湿度グラフ `aclog/graph.png` を作る。
- `acstart.sh <ルール>`: acctl.py を止めて指定ルールで起動し直す。

`venv/`、`aclog/`、`last_aircon.json` は実行時に作られるので管理しない。

## 運用（2026-11-02 時点）

### 制御ルール（acctl.py）
全ルール共通:
- 湿度 > 60% → 除湿 24℃ 風2
- 1:00〜10:00 JST は暖房禁止で off（睡眠中、湿度的につらいため）。冬ルールの前回維持帯でも暖房は続けない
- 目標と実機が違えば送信。同じ状態が1時間続き、最後の送信から60分以上たっていれば同じ設定を再送する
- 外気温は見ない。窓開けは提案しない。風量の指定がなければ風2

| ルール | 冷房 風3 | 冷房 風2 | 送風 風2 | off | 前回維持 |
|---|---|---|---|---|---|
| 厳しめ | > 27.0 | > 26.0 | 使わない | ≤ 24.5 | 24.6〜26.0 |
| 標準 | > 27.5 | > 26.5 | > 26.0 | ≤ 25.5 | 25.6〜26.0 |
| ゆるめ | > 28.0 | > 27.0 | > 26.0 | ≤ 25.0 | 25.1〜26.0 |

冷房はどれも設定 26℃。ルールの切り替えは `./acstart.sh <ルール>`。

### 夏（旧ルール、別名: ゆるめ / 標準 / 厳しめ）
上表のとおり。`T<24.5 → heat22 風2`（1:00〜10:00 JST は off）。

### 冬
暖房を入れてからすぐ切らないよう、オンとオフのあいだは前回維持。
1:00〜10:00 JST は暖房せず off（オン閾値未満でも前回維持帯でも）。

| ルール | 暖房オン | 設定 | オフ | 前回維持 | 冷房26℃風2 |
|---|---|---|---|---|---|
| 冬ゆるめ | < 24.0 | 23℃ 風2 | > 25.5 | 24.0〜25.5 | > 28.0 |
| 冬標準 | < 25.0 | 25℃ 風2 | > 26.0 | 25.0〜26.0 | > 27.5 |
| 冬厳しめ | < 25.5 | 25℃ 風2 | > 26.5 | 25.5〜26.5 | > 28.0 |


### アシスタント（ito）の役割
- 30分ごと: acctl.py が生きているか確認し、止まっていれば再起動するだけ。ログもグラフも読まず、定期報告はしない。再起動に失敗したときだけ知らせる
- 毎日 21:00 ごろ JST: `acgraph.py` でグラフを作り、画像だけをチャットに貼る
- 頼まれたとき: エアコン・灯り・おやすみの操作、温度確認、ルールの切り替えと変更
- ルールやコードを変えたら、ブランチを切って PR を出し、自分でマージする
